# Portfolio Website --- Implementation Phases

**The project has exactly four phases. Do not add extra phases.**

## Phase 1 --- Foundation and Project Setup

**Goal:** Establish the project structure and implement the shared
visual foundation.

Tasks: - Select and document the implementation stack. - Create the
project folders and reusable layout/components. - Set navy,
white/light-gray, and teal design tokens. - Implement responsive
navigation, footer, typography, spacing, and shared buttons. - Add page
structure and SEO metadata foundations. - Create clearly labeled
placeholders for the profile photo, CV, and project images.

Deliverables: - Runnable project scaffold - Shared design system -
Responsive navigation and footer - Setup instructions

Completion criteria: - Project runs locally using documented commands. -
Shared layout works on mobile, tablet, and desktop. - No personal
details or achievements have been invented.

## Phase 2 --- Portfolio Pages and Content

**Goal:** Build the visible portfolio experience using only confirmed
information.

Tasks: - Implement Home, About, Skills/Services, Projects, CV, and
Contact pages or equivalent sections. - Add the approved biography and
education details. - Add eBay, Etsy, E-commerce, and Basic Web
Development cards with honest descriptions. - Build project cards,
responsive gallery, and image lightbox. - Add social links and the
specified WhatsApp click-to-chat integration. - Add the CV
preview/download state, which remains a placeholder until the real PDF
is supplied.

Deliverables: - Complete responsive front-end pages - Project gallery
structure and documented project data format - WhatsApp links and social
links - CV section ready for the supplied file

Completion criteria: - Navigation and internal links work. - Placeholder
content is clearly identified. - No fake projects, testimonials,
metrics, client names, or certificates appear.

## Phase 3 --- Contact Form, Security, and Functional Integration

**Goal:** Connect interactive features to real services and handle user
data responsibly.

Tasks: - Implement contact form validation and accessible error/status
messages. - Connect the form to a real email provider or backend. - Add
server-side validation, spam protection, and safe error handling. - Keep
secrets and API keys out of browser code. - Verify WhatsApp, email,
Instagram, and LinkedIn destinations. - Add safe project-image handling
if upload functionality is implemented. - Add access control and
authorization before implementing any admin panel.

Deliverables: - Tested contact form integration - Security/configuration
documentation - Verified external links - Clear notes for any
integration that still requires owner credentials

Completion criteria: - Form success is shown only after real backend
confirmation. - Failed submissions produce an honest error message. - No
credentials or confidential client data are exposed. - Any unimplemented
integration is explicitly documented as incomplete.

## Phase 4 --- Testing, Deployment, and Handover

**Goal:** Verify the site and prepare it for publication and owner
maintenance.

Tasks: - Test responsive behavior across common mobile, tablet, and
desktop sizes. - Test keyboard navigation, focus states, form labels,
and reduced-motion behavior. - Check page titles, descriptions, image
optimization, and social links. - Check all files and project
placeholders. - Provide deployment instructions for the chosen host and
required environment variables. - Document how to add, edit, and remove
projects and replace the CV/profile photo. - Provide a final checklist
of owner-supplied assets and unconfirmed service details.

Deliverables: - Tested website project - Deployment and maintenance
guide - Remaining-assets checklist - Final list of known limitations

Completion criteria: - No known broken navigation or placeholder links
presented as working features. - Deployment steps are reproducible. -
All unfinished integrations and missing assets are clearly listed.
